# 42usb

Linux의 홈 데이터를 ext4 USB로 옮기고, 원래 위치에 심볼릭 링크를 남기는 명령행 도구입니다. `restore`로 데이터를 홈에 되돌릴 수 있습니다.

사용자 이름과 USB 이름을 코드에 고정하지 않습니다. 프로젝트 폴더를 복사하거나 Git 저장소로 공유하면 다른 사용자도 설치할 수 있습니다.

## 설치

필요한 환경:

- Linux, Python 3.8 이상
- `rsync` (`--fsync` 지원 버전), `lsblk`, `findmnt`
- 쓰기 가능한 ext4 USB 파일시스템

받은 프로젝트 폴더에서 실행합니다. 관리자 권한이나 Python 패키지 다운로드는 필요하지 않습니다.

```sh
sh install.sh
```

실행 파일을 `~/.local/bin/42usb`에 복사합니다. 기존 파일이 있으면 덮어쓰지 않습니다. 해당 디렉터리가 PATH에 없다면 셸 설정에 다음을 추가합니다.

```sh
export PATH="$HOME/.local/bin:$PATH"
```

다른 설치 위치도 지정할 수 있습니다.

```sh
sh install.sh "$HOME/bin"
```

설치 없이 프로젝트 폴더에서 `python3 42usb.py ...`로 실행할 수도 있습니다.

## 사용법

```sh
# USB 장치 수, 파티션 파일시스템, 레이블, 마운트 위치 확인
42usb list

# Neovim을 종료한 뒤 데이터 이동
42usb ~/.local/share/nvim

# USB의 데이터를 홈으로 복원
42usb restore ~/.local/share/nvim

# 42_home 대상 심볼릭 링크, USB 마운트·용량, 미완료 작업 확인
42usb status
```

USB에 여러 파일시스템이 있으면 번호를 선택합니다. 하나인 경우에도 장치 경로와 UUID, 이동 경로, **데이터 용량과 도착지 남은 용량**을 보여 주고 `yes` 확인을 받습니다. 데이터 용량은 실제 디스크 점유량과 파일 크기 합계를 함께 표시합니다. 복원 시에도 같은 정보를 표시합니다. 대상 데이터를 사용하는 프로그램을 먼저 종료하세요. 열린 파일과 작업 디렉터리를 `/proc`에서 가능한 범위 내에서 점검하지만 모든 프로그램의 쓰기를 차단하는 것은 아닙니다.

`/home/.local/share/nvim`은 일반적인 사용자 홈 경로가 아닙니다. `~/.local/share/nvim`, `$HOME/.local/share/nvim` 또는 `/home/사용자명/.local/share/nvim`을 사용하세요. 상대 경로는 현재 작업 디렉터리 기준입니다.

## 저장 구조

홈 디렉터리를 기준으로 한 상대 경로를 유지합니다.

```text
이동 전
  $HOME/.local/share/nvim/                  실제 데이터

이동 후
  USB/42_home/.local/share/nvim/            실제 데이터
  $HOME/.local/share/nvim -> USB/42_home/.local/share/nvim

복원 후
  $HOME/.local/share/nvim/                  실제 데이터
```

`42_home`과 필요한 중간 디렉터리는 없을 때 생성합니다. 이미 있으면 재사용하지만 최종 대상 경로가 있으면 병합하거나 덮어쓰지 않습니다. 복원 성공 후 USB의 해당 데이터는 삭제하며, 비어 있는 상위 디렉터리는 남길 수 있습니다.

## 상태 확인

`42usb status`는 데이터를 변경하지 않고 다음을 표시합니다.

- 연결된 USB 장치 수와 각 파일시스템의 형식·마운트 위치·UUID
- 마운트된 USB별 전체 용량과 현재 사용자가 사용할 수 있는 남은 용량
- 각 USB의 `42_home` 실제 점유량 및 파일 크기 합계
- 홈 내부에서 대상 경로에 `42_home` 디렉터리가 포함된 심볼릭 링크만 표시 (해당 경로의 끊긴 링크 포함)
- USB 연결 해제, 미마운트, 마운트 위치 변경, 대상 데이터 누락, UUID 불일치
- 중단되거나 정리가 끝나지 않은 작업 기록

심볼릭 링크를 따라 다른 디렉터리를 재귀 탐색하지 않고, 용량 계산에서 하드 링크는 한 번만 셉니다. `42_home`이 없으면 0으로 표시하고 USB가 마운트되지 않았으면 용량 계산 불가를 표시합니다. 파일이 많으면 용량 계산에 시간이 걸릴 수 있습니다.

42usb로 이동한 경로의 USB UUID는 `~/.42usb-state/registry`에 저장합니다. 기존에 수동으로 만든 링크도 대상 경로에 `42_home`이 포함되어 있으면 표시하지만, 원래 USB UUID가 기록되지 않은 링크는 현재 마운트·대상 존재 여부까지만 확인할 수 있습니다. 일반 링크와 `42_home_backup`처럼 이름만 비슷한 경로는 제외합니다. 홈 탐색은 현재 홈 파일시스템 안에서 수행하며 별도 하위 마운트는 탐색하지 않습니다.

일반 파일과 디렉터리를 지원합니다. 하위 심볼릭 링크는 링크 자체로 복사하고 파일 권한·수정 시각·ACL·확장 속성·이동 범위 내부의 하드 링크 관계를 보존합니다. 소유자와 그룹은 실행 사용자 및 대상 디렉터리의 정책을 따릅니다. 외부 파일과의 하드 링크 관계는 유지되지 않습니다.

## 데이터 보호 동작

1. 실제 USB인지, ext4인지, 마운트되어 있는지, 쓰기 가능한지 확인합니다. 자동 마운트·포맷은 하지 않습니다.
2. USB의 UUID와 마운트 정보를 전환 직전에도 재확인합니다.
3. 여유 공간을 확인하고 대상 디스크의 임시 디렉터리에 복사합니다.
4. `rsync` 체크섬으로 파일 내용과 메타데이터를 확인합니다.
5. 원본 이름을 임시 백업 이름으로 바꾸고 다시 검증한 뒤 경로를 전환합니다.
6. 마지막 검증 후에만 이전 복사본을 정리합니다.

동일 사용자의 동시 42usb 작업은 잠금으로 차단합니다. 진행 상태와 임시 경로는 `~/.42usb-state`에 기록합니다. 일반적인 전환 전 오류는 원래 경로로 되돌립니다. 전환 후 오류는 새 데이터에 쓰기가 발생했을 수 있으므로 자동으로 되돌리지 않고 기록과 남아 있는 복사본을 보존합니다.

홈 자체, 홈 외부, 42usb 실행 파일과 작업 기록을 포함하는 경로, 상위 경로에 심볼릭 링크가 있는 경우, 하위 마운트·소켓·파이프·장치 파일은 거부합니다. 이동 범위 바깥을 가리키는 상대 심볼릭 링크도 이동 후 의미가 바뀔 수 있어 거부합니다.

복원은 홈의 심볼릭 링크가 선택한 USB의 정확한 대상 경로를 가리킬 때만 진행합니다. 42usb가 기록한 UUID가 있으면 원래 USB와 일치하는지도 확인합니다. 다른 USB나 다른 경로를 가리키는 링크는 삭제하지 않습니다.

## 작업이 중단된 경우

USB를 원래 마운트 위치에 다시 연결하고 대상 프로그램을 종료한 뒤 `42usb status`를 실행합니다. 기록이 남아 있으면 새로운 이동·복원은 차단됩니다. SIGKILL이나 전원 차단 시 자동 원상복구까지 보장하지 않습니다.

기록의 주요 필드:

| 필드 | 의미 |
| --- | --- |
| `local`, `remote` | 원래 홈 경로, USB 데이터 경로 |
| `source`, `destination` | 해당 작업의 출발·도착 경로 |
| `stage` | 임시 복사본을 보관하는 디렉터리 |
| `backup` | 이름을 바꿔 보존한 이전 원본 |
| `link_backup` | 복원 중 임시 보관한 홈 심볼릭 링크 |
| `phase` | `copying`, `switching`, `published` 진행 단계 |

기록은 작업 직전/직후에 저장되므로 `phase`만 보고 삭제하지 말고 실제 경로를 함께 확인해야 합니다. `backup` 또는 전환된 최종 경로에 완전한 데이터가 남아 있는지 먼저 확인하세요. 전환 후 양쪽에서 변경이 일어났다면 필요한 내용을 병합한 뒤 정리해야 합니다. 이 버전은 중단 작업을 자동 복구하는 명령을 제공하지 않습니다. 경로 복구와 데이터 검증이 끝난 뒤에만 해당 작업의 JSON/임시 기록을 제거하세요.

## 사용 시 알아둘 점

- USB가 분리되어 있으면 이동한 데이터를 사용하는 프로그램은 정상 동작하지 않을 수 있습니다.
- 심볼릭 링크는 절대 마운트 경로를 저장합니다. 다른 PC에서 마운트 경로가 바뀌면 자동으로 링크를 수정하지 않습니다.
- `42_home`은 사용자별 하위 폴더를 추가하지 않습니다. 여러 계정이 하나의 USB를 쓰면 같은 상대 경로가 충돌할 수 있으며, 기존 데이터는 덮어쓰지 않습니다.
- 복원 중에는 홈에 완전한 복사본을 만들 공간이 필요합니다. 공간 계산은 보수적이며 하드 링크·희소 파일의 실제 점유량보다 크게 계산할 수 있습니다.
- USB 분리·전원 차단과 계속 쓰는 프로그램까지 완전히 보호할 수는 없습니다. 중요한 데이터는 별도 백업을 유지하세요.

## 테스트

```sh
make check test
```

테스트는 임시 디렉터리를 이용하며 실제 홈 데이터나 USB 데이터를 옮기지 않습니다. 이동·복원, 내용/권한/시간/확장 속성 보존, 경로 충돌, 복사·검증 실패, 정리 실패, USB 분리 시뮬레이션, 부족한 공간, 잘못된 링크 등을 검사합니다. 실제 USB 분리나 정전 테스트를 대체하지 않습니다.

## 제거

필요한 데이터를 먼저 `42usb restore PATH`로 복원한 뒤 설치한 `42usb` 실행 파일만 삭제하면 됩니다. 프로그램을 제거해도 데이터와 심볼릭 링크는 자동으로 복원되지 않습니다.
